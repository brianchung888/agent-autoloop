## 1. 這是什麼、解決什麼問題

平常用 Claude Code、Codex 這類命令列 Agent，幾乎都是「人守在終端機前面」：你打一句話，盯著它跑，等它問下一步。窗口一關、人一走開，事情就斷在那裡。

**agent-autoloop 是一個極輕量的自動化中台（hub）**，裝在你自己的 Mac / Linux / Windows 11 上。它把「排程與派工」做成一個零外部依賴的核心，把其他東西全部拆成可抽換的插件：事件從哪來、哪個 Agent 去做、要你拍板時從哪個通道找你、甚至 CI/CD 上線流水線。

一件事在裡面怎麼轉：

1. **事件進來** — 早上九點的排程、GitHub 新開的 Issue、業務系統報的錯，都變成一條標準事件送進中台。
2. **按規則派工** — 中台照你寫的 `rules.json` 決定交給哪個 Agent、在哪個目錄做。同一件事排隊時又來的訊息會合併成一輪。
3. **做完一輪就退出** — Agent 把結果寫在最後一條回覆裡，進程直接結束。
4. **拿不準才問你** — 碰到刪資料、重啟服務、花錢、對外發訊息這類事，中台推一張卡片給你（飛書 / 桌面通知 / Webhook）。**等你回覆的這段期間它不佔進程、不花 Token。** 你三天沒回，這三天就真的沒有 Agent 在跑。
5. **你拍板，它接著做完** — 你選完，它接回原來的對話把剩下的做完。

能自己搞定的就直接辦完，或者約個時間（例如半小時後）再醒來複查，全程不打擾你。

幾個設計上的重點（README「內核的四個機制」）：

- **掛起零消耗**：等你拍板時進程直接退出，等待狀態存在資料庫裡。
- **事件溯源**：所有狀態都從一條只追加的日誌算出來，日誌和索引在同一個交易裡落盤才應答。任何一輪為什麼跑、結果是什麼，一條命令就查得到（`agent-autoloop why`）。
- **指令資料分離**：Issue 的標題正文等外部文字只當資料放進檔案，不拼進提示詞。用哪個 Agent、在哪個目錄、什麼權限，只由你本機的規則決定；事件裡夾帶 `cwd` / `agent` / `access` 會被直接拒收。
- **跳數熔斷**：Agent 交回的事件再派給 Agent，層數一路累加，超過 8 層就只記錄不再派活，並發一張卡片告訴你。

核心約 1650 行、零執行時依賴；不讀系統時鐘、不用隨機數、不主動向外發請求。

**沒有網頁後台。** 要看全局就敲 `agent-autoloop status`。

### 用量與合規

中台直接呼叫你本機已經安裝並登入好的 CLI，不會讀取或轉存你的帳號憑證。**模型呼叫的費用算在你自己的帳號名下。** 高頻自動化場景下各家廠商通常更建議用 API Key（個人訂閱額度主要是給日常人工互動的）。

## 2. 安裝

支援 **macOS、Linux、Windows 11**。三種裝法：

| | 原始碼安裝（預設） | 單一二進位 |
|---|---|---|
| 前置 | Node.js 24+、Git | 無 |
| 下載體積 | 約 1.5 MB | 約 96 MB（裡面就是一整個 Node） |
| 怎麼升級 | `agent-autoloop update` | `agent-autoloop update`（自己換掉自己） |
| 第三方 `.ts` 插件 | 可以 | 不行，要帶 `runtime: "process"` |
| 資料、規則、密鑰 | 都在 `~/.agent-autoloop` | 一樣，兩種裝法可以互換 |

共同前置：一個**你已經登入好**的命令列 Agent（Claude Code、Codex，或任何能收提示詞、印出最後一條回覆的 CLI）。不需要 GitHub 帳號、不需要 `gh`（除非你要用 GitHub Issue 輪詢或 PR 交付）。

### 2.1 Windows 原生（install.ps1）

**原生支援，不需要 WSL2，也不需要管理員權限。**

```powershell
irm https://raw.githubusercontent.com/brianchung888/agent-autoloop/main/install.ps1 | iex
```

它做的事（照 `install.ps1`）：

1. 檢查有沒有 `git`、有沒有 `node` 且主版本 ≥ 24。沒有就印 winget / nvm-windows 的裝法然後退出。
2. 建 `%USERPROFILE%\.agent-autoloop`，用 `icacls` 把權限鎖到當前使用者。
3. 把公開 repo 的**最新 Release**（通過全部檢查的版本）clone 到 `%USERPROFILE%\.agent-autoloop\app`。
4. 寫一個 `agent-autoloop.cmd` 到 `%USERPROFILE%\.local\bin`，裡面呼叫 `node --disable-warning=ExperimentalWarning <app>\bin\agent-autoloop.ts %*`。
5. 把 `%USERPROFILE%\.local\bin` 加進**你自己的** User PATH（走 `[Environment]::SetEnvironmentVariable`，不用 `setx` — `setx` 會把超過 1024 字的 PATH 截短），**不動系統 PATH**。
6. 跑 `agent-autoloop init`（已經裝過就印「更新好了。」然後 `service install`）。

> **裝完要重開一個終端機**，`agent-autoloop` 才認得。如果沒認到，它會自己印出來：
>
> ```text
> 直接打 agent-autoloop 运行不了这个程序：要么这个终端的 PATH 还是旧的（重开一个就好），要么排在前面的是另一个同名程序。
> 也可以每次写完整路径：
>   node --disable-warning=ExperimentalWarning "C:\Users\你\.agent-autoloop\app\bin\agent-autoloop.ts"
> ```

要從**本機 repo** 裝（不走 GitHub）：

```powershell
$env:AGENT_AUTOLOOP_REPO = "C:\path\to\agent-autoloop"
powershell -ExecutionPolicy Bypass -File C:\path\to\agent-autoloop\install.ps1 --agent codex
```

這時安裝器 clone 的是本機 repo 的 HEAD，`update` 也跟著那個 repo 走，不看 Release。**已經裝過時這個變數不起作用**，還跟著原來的來源；要換來源先 `agent-autoloop uninstall` 再裝。

Windows 上有四處降級，裝之前先知道（細節見 [第 8 章](#8-windows-專章)）。

### 2.2 macOS / Linux（install.sh）

```bash
curl -fsSL https://raw.githubusercontent.com/brianchung888/agent-autoloop/main/install.sh | sh
```

它做的事（照 `install.sh`）：

1. 檢查 `git`、`node` ≥ 24。
2. `mkdir -p -m 700` + `chmod 700` 建資料目錄。
3. clone 最新 Release 到 `~/.agent-autoloop/app`。
4. 把 `agent-autoloop` 做成 symlink 放到 PATH 上第一個可寫的目錄（優先 `~/.local/bin`）。
5. 跑 `agent-autoloop init`。

不用 sudo、不覆蓋其他同名程式。Homebrew 的 `node@24` 預設不進 PATH，裝好後還要：

```bash
export PATH="$(brew --prefix node@24)/bin:$PATH"
```

本機 repo 安裝 + 指定 Agent：

```bash
AGENT_AUTOLOOP_REPO=/path/to/agent-autoloop sh /path/to/agent-autoloop/install.sh --agent codex
```

`install.sh` / `install.ps1` 後面接的參數會直接傳給 `init`：`--agent claude|codex`、`--command '某個命令 {prompt}'`、`--port 3350`、`--no-service`。不指定 `--agent` 時會偵測本機裝好的 Agent，第一個拿來試跑。

### 2.3 單一二進位（這台電腦上沒有 Node）

每個 Release 另附一個單檔可執行程式，三個平台各一個，旁邊各有一份 `.sha256`。

> **還沒發版之前**：GitHub 上還沒有這些檔案。想先試二進位，請在原始碼目錄跑 `pwsh scripts/build-binary.ps1`，會產出 `build\agent-autoloop.exe`（約 96 MB），功能與 Release 版相同，只是檔名不同；下面的指令把檔名換成它即可。**沒有安裝腳本可跑，因為沒有東西要安裝 — 這個檔案就是整個程式**，放哪裡都行（放在 PATH 上某個目錄最省事）。

```powershell
# Windows：先對校驗和，再跑 init
certutil -hashfile .\agent-autoloop-windows-x64.exe SHA256
.\agent-autoloop-windows-x64.exe init
```

```bash
# macOS / Linux
shasum -a 256 ./agent-autoloop-macos-arm64
chmod +x ./agent-autoloop-macos-arm64
./agent-autoloop-macos-arm64 init
```

#### SmartScreen 會攔

這個檔案**沒有簽章**：注入那一步會破壞 `node.exe` 原本的 Authenticode 簽章，所以產物是「未簽章」而不是「簽章壞了」。第一次執行會彈「Windows 已保護你的電腦」，要點 **更多資訊 → 仍要執行**。下載時瀏覽器也可能先說一句。

**對完 `.sha256` 再放行** — 那串校驗和是唯一能確認這個檔案沒被換過的東西。要對的是 Release 上那一份 `.sha256`；同一個 commit 自己再 build 一次 **SHA256 不會一樣**（blob 裡帶著 V8 的 code cache，由建置機器的 runtime 產生），所以這不是可重現建置，別拿自己重建的那份去比。給組織內部分發時，用組織的憑證自己重簽一次最省事。

#### 升級（二進位）

同樣是 `agent-autoloop update`，**它自己換掉自己**：

1. 問最新 Release 是哪一版，下載這台電腦這個平台的那一個和旁邊的 `.sha256`。
2. 對完校驗和才動手。
3. 往 `AGENT_AUTOLOOP_HOME/stop` 寫一個檔案等中台收尾。
4. 把手上這個 exe 改名成 `.old`、把下載的 `.new` 改成正名，再重啟常駐（排程任務指的是路徑不是檔案，所以不用重裝）。
5. `.old` 下次啟動時自己清掉 — Windows 不讓刪正在跑的 exe，但允許改名，這整套就是為這點設計的。

出錯時一律不動手上這一版：下載斷了、`.sha256` 對不上、改名沒成功，都會把下載刪掉、把原檔放回去，並說清楚發生了什麼。**只有一件事收不回來** — 中台已經被停過一次，所以訊息裡會寫它有沒有重新啟動。沒網、被限流、或這個平台 Release 裡沒建，都會直接說出來並給手動下載的地址。

**別在中台還在跑的時候直接覆蓋這個 exe — Windows 會直接拒絕。**

手動升級那條路還在：到 Release 頁面取檔案、對校驗和、寫 `stop` 檔、換掉檔案、再啟動一次。

#### 二進位的其他差異

- 內建插件是編進去的；`agent-autoloop add` 裝的第三方 `.ts` 插件會收到一句「這個打包版跑不了外部的 .ts 檔，在 plugin.json 裡寫 `{"runtime":"process",…}`」。
- 開發用的隨機模擬（`sim/`）在二進位裡到不了；`conformance` 到得了，用法和原始碼模式一樣。
- `uninstall` 刪的是它自己放進去的東西（常駐、Skill、PATH 上的連結），**不刪你下載的那個檔案** — 那是你放的。
- 規則、密鑰、紀錄都在資料目錄裡不在這個檔案裡，所以換檔案不丟任何東西；兩種裝法來回換也不會觸發投影重建（兩種模式算出來的 format hash 逐字相同，`tests/sea-format.test.ts` 釘著這條）。

### 2.4 升級與資料目錄

- 安裝和 `agent-autoloop update` 都裝**最新的 Release**，`main` 上還沒發布的改動要等下一個 Release。
- 程式在 `~/.agent-autoloop/app`（Windows：`%USERPROFILE%\.agent-autoloop\app`），配置和紀錄在 `~/.agent-autoloop`。
- 升級後要同步重啟中台與接單程式（`service install` 會做）。
- 升級時若投影格式有變，會自動從舊日誌逐條重建，歷史多時首次啟動要等（110 萬條約 43 秒）。原日誌和已發出的卡片連結保留，不用手動遷移。
- `master.key` 壞了中台會拒絕啟動：從備份恢復；沒備份就刪掉它，重啟會產生新的，但**已發出的卡片連結和正在跑的輪次會失效**。

## 3. 第一個小時：init → up → try → answer → status → doctor

下面的輸出都是從程式原始碼的字串或 `scripts/install-smoke.ps1` 的斷言抄來的真實文字。

### 3.1 `init` — 在這台電腦上裝好

```bash
agent-autoloop init [--agent claude|codex] [--command '某个命令 {prompt}'] [--port 3350] [--no-service] [--lang zh-TW|zh-CN]
```

**它會改什麼：**

- 建 `~/.agent-autoloop`（並上鎖：POSIX `0700`，Windows `icacls`）與 `~/.agent-autoloop/try`
- 寫 `~/.agent-autoloop/rules.json`（起始規則：一個 `local` 來源、偵測到的 Agent、`desktop` 通道、一條「试一下」規則）— **只有在這個檔案還不存在時才寫**
- 寫 `~/.agent-autoloop/config.json`（中台網址、監聽位址、worker 密鑰、source 密鑰、owner 密鑰、desktop 通道密鑰）
- 把 `skills/agent-autoloop` 接到 `~/.claude/skills/` 和 `~/.codex/skills/`（存在的那些；Windows 用 junction，不行就複製並記在 `~/.agent-autoloop/skill-link.json`）
- 裝常駐服務（沒給 `--no-service` 時）：macOS launchd / Linux systemd --user / Windows 排程任務

輸出長這樣：

```text
装好了。
  Agent：Codex
  通道：桌面通知
  规则：C:\Users\你\.agent-autoloop\rules.json

运行 agent-autoloop try 跑一遍完整流程。
```

給了 `--no-service` 時最後一句改成：

```text
先运行 agent-autoloop up 启动中台，再开一个终端运行 agent-autoloop try 跑一遍完整流程。
```

幾個會擋住你的錯誤：

```text
已经装过了：C:\Users\你\.agent-autoloop\config.json
```

```text
这台电脑上没找到 Claude Code 或 Codex。先装好并登录，或者用 --command 指定别的命令行 Agent，比如 --command 'hermes chat -Q -q {prompt}'
```

`init` 的參數檢查很嚴：`init -p 4000` 這種寫錯的旗標會被直接拒絕（否則它會默默用預設 port 裝下去）：

```text
不认识的参数：-p 4000
```

### 3.2 `up` — 啟動中台

```bash
agent-autoloop up
```

平時由系統服務呼叫，你自己跑是在沒裝服務的時候。**它會一直跑在前景**，所以要另開一個終端機做後面的事。

**它會改什麼：** 建 `~/.agent-autoloop/up.pid`（單例鎖）；Windows 上還會寫 `~/.agent-autoloop/logs/up.log`（上限 8 MB，自己輪替）；載入 `secrets.env`；開 HTTP 監聽；啟動 worker 與各通道迴圈。

健康檢查端點：`http://127.0.0.1:3350/healthz`（回 200 且 `{"ok":true,...}`）。

> **Windows 上停它別直接殺進程。** 往 `AGENT_AUTOLOOP_HOME` 下寫一個空的 `stop` 檔案，中台看到就自己收尾（`agent-autoloop uninstall` 也是這麼停的）。Windows 沒有 SIGTERM 可送，硬殺會留下 `up.pid` 和沒關的連線。

### 3.3 `try` — 用你的 Agent 真實跑一遍

```bash
agent-autoloop try
```

**它會改什麼：** 往中台發一條 `try.start` 事件（會寫進事實日誌、會真實呼叫你的 Agent、**會用掉你的模型額度**），然後輪詢狀態最多 5 分鐘。

```text
事件发出去了，Agent 开始干活……

Agent 结束了这一轮，问了你一个问题。它现在不占进程、不花 Token。

【等你决定】#1 试跑：选一个颜色
这是一次试跑，选哪个都行。
  1. 蓝色
  2. 绿色
回答：agent-autoloop answer 1 <序号>
答完运行 agent-autoloop status，能看到它接着把活干完。
```

- **互動終端機**裡它會直接問你「选几？」，輸入數字 Enter 就好。
- **非互動終端機**（CI、被 Agent 呼叫）它印完上面這段就退出 — **這是正常等待，不是失敗**。

接不上中台時：

```text
连不上中台（<原因>）：先 agent-autoloop up 或 agent-autoloop service install
```

Agent 沒跑成時：

```text
Agent 没跑成：<原因>
运行 agent-autoloop doctor 看看。
```

五分鐘沒結果時：

```text
五分钟没等到结果。运行 agent-autoloop doctor 看看。
```

### 3.4 `answer` — 拍板

```bash
agent-autoloop answer 1 2
```

**它會改什麼：** 把這張卡片的回答寫進事實日誌，並叫醒原來的會話接著做。

```text
收到，Agent 接着干。
```

其他可能的回覆：

```text
结案了。
```

```text
这张卡片已经处理过了，这次没有改动。
```

回答一張不存在的卡片會留下 exit code 1 和一句錯誤（`install-smoke.ps1` 用 `answer 999999 1` 驗這條路徑）。

通告（notice）類的卡片不用寫序號，直接 `agent-autoloop answer <卡片>`。另一條路是 `agent-autoloop resolve <卡片> <結果>`：這件事不用決定了，順手寫一句處理說明留在卡片上。

### 3.5 `status` — 現在什麼情況

```bash
agent-autoloop status
```

**它會改什麼：** 什麼都不改，只讀 `/v1/state`。

```text
在跑 0 · 排队 0 · 今天做完 2 · 等你 0
今天 2 轮 · 12.3 万 Token · $0.04    最近 7 天 2 轮 · 12.3 万 Token · $0.04

● Codex（your-pc）
● 桌面通知

最近的卡片
  #1 试跑：选一个颜色：绿色。你选了绿色，试跑通过

最近几轮
  #2 试一下 做完了：你选了绿色，试跑通过
  #1 试一下 做完了：问了一个问题
```

（費用那一行的格式由 `cli/spend.ts` 決定；沒上報用量的輪次會寫成 `Token 没上报` / `费用没上报`，部分沒上報會加 `（N 轮没上报）`。上面的 Token / 費用數字是示意，實際依你的 Agent 回報。）

看到「试跑通过」就算接通了。`install-smoke.ps1` 另外斷言 `status` 裡會有 `最近 7 天 2 轮`。

區塊順序是：總覽 → 費用 → Agent/通道上下線 → 等你的卡片 → 定時 → 最近的卡片（最多 5 筆）→ 最近幾輪（最多 8 筆）→ 沒有規則接的事件（最多 5 筆）。

`agent-autoloop status --json` 輸出 `/v1/state` 的原樣結構，給腳本和看板用。

### 3.6 `doctor` — 查哪裡沒配好

```bash
agent-autoloop doctor
```

**它會改什麼：** 什麼都不改（會讀 `permissions.json` 並在需要時把 SKILL.md 寫出到 HOME — 這是等效冪的）。

三個符號（`cli/main.ts` 的 `say` / `aside`）：

| 符號 | 意思 | 影響 exit code？ |
|---|---|---|
| `●` | 好了 | 不 |
| `○` | 紅項 | **會**（有任何一條 ○ 就 exit 1） |
| `◐` | 降級說明（能用，只是不如字面承諾的那麼多） | 不 |

它依序查：Node 版本 → 有沒有裝好 → 檔案權限 → 規則檔 → 通道有沒有寫 `answerers` → 系統服務 → 中台 `/healthz` → 每個 Agent 上下線與可用性 → 每個通道上下線 → 有沒有接通道。

典型輸出（Windows、沒裝服務）：

```text
● Node 24.21.0
● 规则 C:\Users\你\.agent-autoloop\rules.json
○ 系统服务没在跑：agent-autoloop service install
● 中台 http://127.0.0.1:3350（d09a7e8c1234）
● Codex（your-pc）在线
● Codex 可以用
◐ 桌面通知不可用：Windows 上没有可用的通知程序，卡片会跳过通知
◐ 只接了桌面通知，而这台电脑弹不出通知：Agent 问你时得自己运行 agent-autoloop status 看。要发到飞书、钉钉这些地方，接法见 C:\Users\你\.agent-autoloop\skills\agent-autoloop\SKILL.md
```

Windows 上裝了排程任務時，「系统服务在跑」下面會多一條：

```text
◐ Windows 上靠计划任务常驻：停了之后最多等 5 分钟才会自己回来。
```

加了網域、不讓「登入時啟動」的電腦改成：

```text
◐ Windows 上靠计划任务常驻，而这台电脑不让登录时就启动（通常是加了域）：登录后和停了之后都最多等 5 分钟。
```

> 沒裝系統服務時 `doctor` 一定會顯示服務沒在跑，**不要為了消掉這條提示去裝真的服務** — 檢查中台、Agent 和通道有沒有在線就夠了。

```bash
agent-autoloop --version      # 版本和當前 commit
```

### 4.1 完整命令清單

這份表直接出自 `cli/main.ts` 的 `HELP` 與 `commands` 表（**命令清單的權威來源**）。「會改什麼」是我讀程式碼後的註記。

| 命令 | 做什麼 | 會改什麼 |
|---|---|---|
| `init [--agent claude\|codex] [--command '… {prompt}'] [--port 3350] [--no-service] [--lang zh-TW\|zh-CN]` | 在這台電腦上裝好 | 建 HOME、寫 `rules.json` / `config.json`、接 Skill、裝服務 |
| `try` | 用你的 Agent 跑一遍完整流程 | 發一條真實事件，用掉模型額度 |

| `conformance <地址> --config <測試憑據檔>` | 在**測試**中台上檢查協議 | 會在那台測試中台寫事件和卡片 |
| `status [--json]` | 誰在線、等你什麼、在做什麼、做過什麼、花了多少 | 只讀 |
| `answer <卡片> [序號] [--text 別的想法]` | 回答一張卡片；通知不用寫序號 | 寫回答事實、叫醒原會話 |
| `resolve <卡片> <結果>` | 這件事不用決定了，寫一句結果 | 結案該卡片 |
| `doctor` | 查哪裡沒配好 | 只讀（會寫出 SKILL.md） |
| `check [檔案]` | 檢查規則檔，**不碰中台**；不寫檔就查 `rules.json` | 只讀 |
| `rules explain` | 按本機 `rules.json` 說明生效的規則、Agent、通道和下次定時 | 只讀，不連中台 |
| `emit <類型> [--dry-run] [--subject x] [--summary x] [--detail x] [--link x] [--id x] [--key 來源密鑰]` | 發一條事件；`--dry-run` 只預演會派給誰 | 不加 `--dry-run` 就真的發事件 |
| `tell <編號> [--task 定時任務名]` | 直接告訴你一件事，內容從 stdin 讀 | 建一張 `fyi` 卡片 |
| `ask --task <定時任務名>` | 定時任務問你一件事；stdin 傳回執那樣的 `ask` | 建一張 `ask` 卡片 |
| `stop <第幾輪>` | 停掉一輪 | 發停止訊號，等整個進程組退出才報告已停 |

| `key remove <種類> <名字>` | **立即**收回一把密鑰 | 長輪詢和日誌訂閱也立即失效 |
| `add <git 地址>` | 安裝插件，不自動更新 | `git clone` 到 `~/.agent-autoloop/plugins/<名字>` |
| `mcp` | 用 stdio 連接 MCP 客戶端 | 依呼叫而定 |
| `join <中台地址> --worker <名字> --key <密鑰> [--no-service]` | 另一台電腦只接活時用 | 寫 `config.json`、裝服務 |
| `backup [目錄]` | 備份資料庫、主密鑰、配置、規則和 `secrets.env` | 寫到目標目錄（預設 `~/.agent-autoloop/backups`） |
| `restore <目錄> [--yes]` | 用一次備份恢復本機資料 | **替換**本機資料庫、主密鑰、配置、規則、`secrets.env`；要先停中台 |
| `update` | 更新到最新發布的版本 | 換程式碼（或換二進位）、重啟常駐 |
| `uninstall [--yes]` | 卸載程式並保留資料 | 停服務、刪自己的程式與連結；**不刪資料目錄** |
| `lang [zh-TW\|zh-CN]` | 這個程式說哪種中文；不寫就說現在說的是哪種 | 寫 `config.json` 的 `lang`（要先 `init`） |
| `--version` | 版本和當前 commit | 只讀 |
| `help` / `--help` / `-h` | 說明 | — |

另有兩個**內部子命令**（不在 help 裡，你不用打）：`internal:plugin`、`internal:launch`。

### 4.2 規則 `rules.json` 怎麼寫

打開 `~/.agent-autoloop/rules.json`。**改完幾秒內自動生效**，不用重啟。寫錯了舊規則繼續跑，並推一張卡片說錯在哪 — 檔案被刪、讀不到也一樣。

每條規則回答五個問題：**什麼事件（`when`）、交給誰（`to`）、在哪（`cwd`）、照什麼做（`skill` / `prompt`）、要不要告訴你（`tell`）**。

最小的例子 — 每天早上九點寫早報：

```json
{
  "name": "早报",
  "when": { "cron": "0 9 * * *" },
  "to": "codex",
  "cwd": "~/notes",
  "prompt": "整理昨天的笔记和提交，写今天的早报。"
}
```

外部事件寫法一樣，只是要先接好來源：

```json
{
  "name": "处理 issue",
  "when": { "source": "github", "types": ["issues.opened"] },
  "to": "codex",
  "cwd": "~/code/app",
  "skill": "handle-issue",
  "parallel": 3
}
```

整份檔案的結構（出自 `docs/protocol.md`「規則」一節，註解是原文）：

```jsonc
{
  "timezone": "Asia/Shanghai", // 定时和“今天”用的时区，默认系统时区
  "askFirst": ["删数据", "停服", "花钱", "对外发消息"], // 只有这几类事 Agent 才先问你
  "sources": { "shop": { "name": "shop" }, "github": { "name": "GitHub", "adapter": "github" } },
  "agents": {
    "claude": { "name": "Claude Code", "worker": "mac-mini", "use": "claude", "model": "…", "effort": "high", "access": "edit" },
    "cursor": { "name": "Cursor", "worker": "mac-mini", "use": "command", "command": ["agent", "-p", "--trust", "{prompt}"] }
  },
  "channels": { "feishu": { "name": "飞书", "answerers": ["ou_xxx"] } },
  "rules": [
    {
      "name": "处理告警",
      "when": { "source": "shop", "types": ["alert.*"] }, // 或 { "cron": "0 9 * * *" }
      "to": "claude",
      "cwd": "~/code/shop",
      "skill": "run-ops",
      "prompt": "按其中……一节处理。",
      "group": "ops",        // 同一组一次一轮，默认就是规则名
      "parallel": 3,          // 按对象分事项；还受 worker.capacity 限制（默认 2）
      "resume": true,         // 同一事项的新事件接着上一轮的会话，默认每次开新会话
      "tell": "needed",       // always / needed（默认）/ never
      "emits": { "source": "shop", "types": ["pr.*"] }, // 回执里能发什么事件，不写就不能发
      "channels": ["feishu"], // 不写就发到所有通道
      "timeout": 180          // 一轮最长跑多久，单位分钟，默认 180
    }
  ],
  "elsewhere": [
    {
      "name": "每周清理", "source": "shop", "to": "claude", "cron": "0 6 * * 0",
      "where": "Claude 应用的定时任务", "cwd": "~/code/shop", "skill": "weekly-sweep"
    }
  ]
}
```

重點整理：

- **`to` 填 `agents` 裡已經有的名字。**
- **`cwd` 要從根說起**，而什麼算根是**讀規則的那台機器**說的：POSIX 上是 `~/` 或 `/`；Windows 上另收 `~\`、磁碟代號（`C:\`）和 UNC（`\\server\share`）。**兩邊不互認** — 寫著 `C:\code\shop` 的規則在 Linux 中台上會被當成寫錯（整份規則不生效，推一張卡片說錯在哪），反之也一樣。所以 `rules.json` 是跟著**中台所在平台**的。
- **`parallel`**：同一個對象的事件要分開處理、互不等待就寫它。一台接單程式同時跑幾輪還受 `config.json` 的 `worker.capacity` 限制（預設 2），要多跑要一起調大。
- **`resume: true`**：同一對象的新事件接著上一輪的會話。預設每次開新會話。上一輪被停掉、可能還在跑、或換了 Agent 時一律開新的。會話越接越長，Token 和費用也跟著漲。
- **`askFirst`**：預設的先問清單。你要 Agent 遇到什麼事一定先問你，就改這裡。
- **`elsewhere`**：你在別的地方（Claude、Codex 應用裡）定時跑的任務。中台不啟動它們，只在 `status` 裡列出來；它們要找你時跑 `agent-autoloop tell <編號> --task <任務名>`（內容從 stdin）。要你拍板的，給這個任務寫上 `cwd` 和 `skill`/`prompt`，任務裡跑 `agent-autoloop ask --task <任務名>`。

改完的三個檢查命令：

```bash
agent-autoloop check                 # 只讀檔案，不碰中台；不寫檔名就查 rules.json
agent-autoloop rules explain         # 列出生效的規則、Agent、通道和下次定時
agent-autoloop emit demo.start --dry-run   # 預演這條事件會派給誰（不連中台、不寫日誌）
```

`check` 成功時：

```text
规则没问题：C:\Users\你\.agent-autoloop\rules.json
```

`emit --dry-run` 開頭是：

```text
预演（按本机 rules.json，不连接中台、不写日志）：
```

真的發事件時（不帶 `--dry-run`）：

```text
交给了：处理 issue
```

或者：

```text
记下了，没有规则接它。
```

> `--dry-run` 不能和 `--key` 一起用：`--dry-run 按这台电脑的来源预演，不能和 --key 一起用`

### 4.3 卡片怎麼回答

中台對 Agent 只有一個約定：**在最後一條回覆裡交代結果**。事情辦完了，正常輸出一句結論就行。需要向你請示時，在回覆末尾附一段 `agent-autoloop` 程式碼區塊：

````text
订单已经核对完毕，库存充足。

```agent-autoloop
{
  "ask": [{
    "title": "怎么发货？",
    "text": "两种方式今天都能发出。",
    "options": ["快递", "自提"],
    "key": "shipping"
  }]
}
```
````

回執裡能寫的東西：

| 欄位 | 意思 |
|---|---|
| `ask` | 提問，帶選項按鈕，等你拍板 |
| `notice` | 通告，不需要回答；標成 `fyi` 的不帶按鈕 |
| `resolve` | 關閉已經解決的卡片 |
| `later` | 預約複查（例如半小時後再醒來看一次） |
| `events` | 觸發新事件（規則要寫 `emits` 才允許） |

**JSON 寫錯了會怎樣：** 中台只讓它在原會話裡重寫最後這段回覆，**不會把已經做完的業務重做一遍**。重寫也失敗時保留原結論，並通知你回執沒有生效（通用命令沒有會話，直接走這一步）。

你這邊回答的三條命令：

```bash
agent-autoloop answer 7 2                    # 選第 2 項
agent-autoloop answer 7 2 --text "顺便看一下退款"   # 選第 2 項，另外加一句
agent-autoloop answer 7 --text "都不要，改成这样"    # 不選，直接寫想法
agent-autoloop resolve 7 已经手动处理完了          # 不用決定了，寫一句結果結案
```

### 4.4 停掉一輪、查為什麼

```bash
agent-autoloop stop 42
```

```text
通知它停了。
```

**它會改什麼：** 發停止訊號，**等整個進程組（Windows 上是整棵進程樹）退出才報告已停**。只有真的「沒有活進程」才交 `cancelled`。

```bash
agent-autoloop why 42            # 這一輪的事件、規則和回執
agent-autoloop why 42 --json     # 原始事實
```

### 4.5 常駐服務

```bash
agent-autoloop service install   # 裝 / 重裝常駐（也會重新接 Skill 連結）
agent-autoloop service remove    # 移除常駐
```

| 平台 | 常駐方式 | 行為 |
|---|---|---|
| macOS | `~/Library/LaunchAgents/agent-autoloop.plist` + `launchctl bootstrap` | 崩了立刻回來 |
| Linux | `~/.config/systemd/user/agent-autoloop.service` + `systemctl --user` | 崩了立刻回來 |
| Windows | **排程任務**（`schtasks`，XML 註冊，不需管理員） | 登入時啟動 + 每 5 分鐘重複觸發；**停了之後最多等 5 分鐘才回來** |

日誌：

- macOS：`~/.agent-autoloop/logs/up.log`
- Linux：`journalctl --user -u agent-autoloop`
- Windows：`%USERPROFILE%\.agent-autoloop\logs\up.log`（上限 8 MB，自己輪替）

伺服器上自己寫的**系統級** systemd unit，名字要和 `agent-autoloop service install` 用的一樣（預設 `agent-autoloop`），`doctor` 才認得出；`agent-autoloop update` 不碰它，更新後要自己 `systemctl restart` 才用上新版。

### 4.6 備份與恢復

```bash
agent-autoloop backup                    # 放在 ~/.agent-autoloop/backups/<時間戳>
agent-autoloop backup D:\backups\al-01    # 放到指定目錄
```

```text
备份好了：D:\backups\al-01
  hub.db、master.key、config.json、rules.json、secrets.env
里面有密钥，把它放到安全的地方；恢复要中台停下来。
```

（檔案清單依 `cli/backup.ts` 實際備份的項目列出，上面那一行的措辭取自 `cli/main.ts` 的樣板。）

中台運行時也能備份。恢復要先停中台：

```bash
agent-autoloop restore D:\backups\al-01 --yes
```

```text
恢复会替换本机的数据库、主密钥、配置、规则和 secrets.env，继续？[y/N]
```

```text
恢复好了。原来的文件在 <安全目錄>。
启动：agent-autoloop up 或 agent-autoloop service install
```

非互動終端機不加 `--yes` 會被擋：

```text
恢复会替换本机数据；确认后运行 agent-autoloop restore <目录> --yes
```

手工備份至少要一起保留 `hub.db` 和權限 0600 的 `master.key`（後者推導輪次和卡片連結的 token）。

### 4.7 多台電腦

手機要批卡片、別人的 Webhook 要進來時，把中台放到一台有公網的機器上：

1. **伺服器**：`sh install.sh --no-service --command true`（這台不跑 Agent，`--command true` 只是佔位），`config.json` 裡 `hub.listen` 用 `127.0.0.1:3350`（要寫成 `主機:端口`，IPv6 用 `[地址]:端口`；只寫端口或 `:端口` 會被拒絕，避免意外監聽所有網卡），`hub.publicUrl` 寫公網地址，去掉 `worker`，再 `agent-autoloop service install`。前面放一個做 HTTPS 的反向代理（Caddy、nginx）。
2. **每台幹活的電腦**：伺服器上 `agent-autoloop key new worker <名字>`，電腦上：

```bash
curl -fsSL https://raw.githubusercontent.com/brianchung888/agent-autoloop/main/install.sh | sh -s -- join https://中台地址 --worker <名字> --key <密钥>
```

幹活的電腦**不用開放任何端口**，它們自己連過去。`rules.json` 的 Agent 寫上對應的 `worker`。

`join` 的保護：已經有 `config.json` 時會拒絕，避免蓋掉現有設定：

```text
已经配置过了：<路徑>。为防止覆盖现有设置，请先备份并手动修改配置。
```

### 4.8 現成的場景模板

每套都帶規則、任務 Skill 和啟用說明，在 `examples/recipes/`：

| 想做什麼 | 已經封裝好的流程 |
|---|---|
| 每日早報（`morning-brief`） | 預設每天 8 點整理本地筆記和 Git 提交，寫入 `briefs/YYYY-MM-DD.md` |
| 跟進 GitHub Issue（`github-issues`） | 每 5 分鐘查新 Issue，在本地改程式碼並通知你查看；不提交、不推送、不回覆 Issue |
| 線上告警排查（`ops-alerts`） | 接收報錯、對照程式碼查原因，需要重啟時發卡片詢問，回答後繼續 |
| 使用者回饋處理（`feedback`） | 重讀回饋當前狀態、修復、交付核實、準備回覆 |
| 網站巡檢（`website-watch`） | 每 5 分鐘檢查狀態和關鍵內容，首次異常交給 Agent，持續異常不重複通知，恢復後更新原卡片 |
| 飛書週報與業務摘要（`feishu-brief`） | 週日 18 點按你的權限讀匯報和指定表格，生成本地摘要 |
| PR 自動交付（`delivery`） | 打上 `deliver` 標籤後，審查 → 等 CI → 合併 → 等發布 → 核對線上版本 |
| Claude 委託 Codex 處理網頁（`browser-handoff`） | 主任務交網頁步驟給 Codex，保留子會話編號 |

**啟用方式：** 打開對應說明 → 把任務 Skill 放進所用 Agent 的 skills 目錄 → 把範例規則合進 `~/.agent-autoloop/rules.json` → 替換電腦名和路徑 → `agent-autoloop check`。

> 回饋處理、網站巡檢和飛書摘要預設用北京時間、只發給本人的飛書私聊。範例資料都是虛構的；腳本和回執只用本地 HTTP 與假飛書 CLI 驗證過，**沒有在真實帳號上跑過完整業務**。

## 5. 接 Agent

### 5.1 內建的 Agent 插件

| `use` | Agent | 實測狀況（README 自述） |
|---|---|---|
| `claude` | Claude Code | 跑通了多輪問答和跨進程會話續接 |
| `codex` | Codex | 跑通了多輪問答和跨進程會話續接 |
| `acp` | ACP（Agent Client Protocol） | 用官方 Codex ACP 轉接器跑通 |
| `dsh` | DeepSeek Harness | 要 0.2.2 或更新；有使用者在 WSL2 上實測跑通問答、用量和 `resume` |
| `command` | 任何能印出最後一條訊息的 CLI | 見下 |

### 5.2 `claude` / `codex`

`init` 會自己偵測。規則裡長這樣：

```json
"claude": { "name": "Claude Code", "worker": "my-pc", "use": "claude", "access": "edit" }
```

`access` 預設 `edit`，三個檔位由插件翻譯成對應 CLI 的權限：

| 插件 | `read` | `edit` | `full` |
|---|---|---|---|
| Codex | `read-only` | `workspace-write` | `danger-full-access` |
| Claude Code | `plan` | `acceptEdits` | `bypassPermissions` |
| DeepSeek Harness | `read-only` | `workspace-write` | `danger-full-access` |
| ACP | Agent 來問時同意讀和搜尋 | 再同意工作目錄內的編輯 | 同意它來問的所有操作 |

> **`access` 不是中台提供的系統沙箱**，是插件翻譯給各家 CLI 的權限模式。你自己的 CLI 設定可能改變上面的能力；`read` 也不代表讀不到本機密鑰。要 `full`（完整權限、不審批）之前先想清楚。
>
> Codex 三個檔位已用插件命令實跑；DSH 和 Claude Code 是依官方文件整理，**沒有呼叫模型實跑**。

#### Windows 上的安裝位置注意（重要）

**Agent 的程式必須是真正的可執行檔（`claude.exe` 這種）。npm 裝出來的 `.cmd` 包裝腳本起不了**，`agent-autoloop init` 會說找不到。

原因在 `worker/agents.ts` 的 `findProgram()`：Windows 上用 `where.exe <名字>` 找，但**只接受結尾是 `.exe` / `.com` 的那一筆**。`.cmd` / `.bat` 是給命令解譯器讀的腳本，不能當程式啟動（Windows 會直接拒絕），所以插件寧願回報「沒裝」也不給你一個第一輪才爆掉的名字。

PATH 上找不到時，兩個插件各自會去找這些地方：

**Claude Code**（`plugins/claude/agent.ts`）
- 桌面 App 自帶的那些版本：`%APPDATA%\Claude\claude-code\<版本>\<build>\claude.exe`（取版本號最新的）
- 獨立安裝：`%USERPROFILE%\.local\bin\claude.exe`、`%LOCALAPPDATA%\Programs\claude\claude.exe`、`%LOCALAPPDATA%\claude\claude.exe`

**Codex**（`plugins/codex/agent.ts`）：Windows 上的候選路徑同樣是 `%LOCALAPPDATA%` 底下那幾個 — 具體清單見該檔案 `elsewhere()`。

如果你的 `claude` / `codex` 只有 npm 的 `.cmd`，兩條路：

1. 改用官方的獨立安裝器 / 桌面 App（會給你 `.exe`）。
2. 用 `--command` 自己把它接起來，指到真正的執行檔（例如用 `node` 跑它的 js 入口）。

### 5.3 `command` — 任何 CLI 一行接入

設 `use: "command"` 並傳入命令陣列。`{prompt}` 作為**獨立參數**傳遞，**不會被當成 shell 程式碼執行**：

```json
"hermes": {
  "name": "Hermes",
  "worker": "my-mac",
  "use": "command",
  "command": ["hermes", "chat", "-Q", "-q", "{prompt}"]
}
```

參數裡可以用的佔位符：`{prompt}`、`{model}`、`{effort}`、`{cwd}`、`{context}`。每個參數只替換一輪 — 替換進去的提示詞原樣傳給程式（提示詞裡寫著 `{cwd}` 或 `$&`，到程式那邊也還是這幾個字）。執行時還有環境變數 `AGENT_AUTOLOOP_CONTEXT`（資料檔）和 `AGENT_AUTOLOOP_RUN`（第幾輪）。

**退出碼不是 0 算沒跑成。**

下面這些命令是 README 整理自各家官方文件，**作者還沒有逐個跑過**：

| Agent | 接入命令 |
|---|---|
| DeepSeek Harness 舊版 | `dsh --profile headless {prompt}` |
| pi | `pi --print {prompt}` |
| OpenClaw | `openclaw agent exec {prompt}` |
| Hermes | `hermes chat -Q -q {prompt}` |
| Cursor | `agent -p --trust {prompt}` |
| WorkBuddy / CodeBuddy | `codebuddy -p {prompt}` |

`command` 只傳參數，**不替任意程式限制權限** — 要限制請按該 CLI 自己的文件設定。`command` 和固定腳本以你本機帳號執行，不受 `access` 約束。

### 5.4 `acp`

```json
"myacp": { "name": "My ACP", "worker": "my-pc", "use": "acp", "command": ["ACP 服務程式"] }
```

支援 v1 的會話新建、恢復、文字與一次性權限請求。先在該 Agent 自己的 CLI 登入。

注意：
- `access` **只管 Agent 主動來問的操作**。規範允許它不詢問就執行，那種操作 `access` 擋不住，要用它自己的模式限制（例如 `command` 裡寫 `env INITIAL_AGENT_MODE=read-only …`）。
- `model`、`effort` **不生效**，要在 Agent 自己那邊設定。

### 5.5 `dsh`（DeepSeek Harness）

要 0.2.2 或更新：

```bash
npm install -g @deepseek-ai/dsh@next --allow-scripts=koffi,node-pty,@deepseek-ai/dsh-subprocess-local
```

**不放行這三個包的安裝腳本，裝完看著正常，一跑才出錯。** `agent-autoloop doctor` 會查版本。

- 能續接原會話、上報 Token（**不報費用**）
- 報 `MISSING_CREDENTIAL` 時把密鑰放進環境變數（Linux 的系統服務放 `~/.config/environment.d/*.conf`）
- `access` 對應它的權限檔位；規則裡的 `model`、`effort` 不起作用
- **沒有可打開的桌面會話連結**
- DSH 預設把會話日誌上傳給 DeepSeek

### 5.6 用量統計怎麼算

`status` 的 Token / 費用是按**完成時間**統計今天和最近 7 天（同一輪重試的已報用量相加，沒上報的輪數會寫出來）。

續接會話也只算這次新增的用量：`~/.agent-autoloop/worker/usage/` 存著相減要用的累計值。沒有紀錄的續接（例如你刪了這個目錄、換了電腦、升級前就有的會話）這次不報 Codex 的 Token 和 Claude Code 的費用，下一次恢復正常。**你自己打開連結在同一個會話裡接著聊用掉的量，會算進下一次續接。** 舊回執不重算。

## 6. 通知通道與 webhook 來源

### 6.1 通道（卡片送到哪找你）

配置在**兩處**，缺一不可：

- `rules.json` 的 `channels`：登記名字和 `answerers`（誰能回答）
- `config.json` 的 `channels`：寫密鑰和選項

拿密鑰：`agent-autoloop key new channel <名字>`（這是新建密鑰）。**改了 `config.json` 要 `agent-autoloop service install` 重啟中台。**

預設每張卡片發到所有通道。某條規則的卡片只想發到某幾個，在那條規則裡寫 `"channels": ["feishu"]`。

#### 桌面通知（`desktop`，預設開啟）

新裝的中台預設開著，兩處各有一個 `desktop`。

- 卡片第一次發送時：macOS 用 `osascript`、Linux 用 `notify-send` 彈一條通知
- 標題「Agent 问你一个问题」，正文是卡片標題和「运行 agent-autoloop status 查看」
- **不能在通知上回答**
- 沒有圖形會話時安靜跳過，問題仍在；通知命令失敗時報告失敗，不會讓中台退出
- **Windows 上一律跳過**（見第 8 章）

不想要就把兩處的 `desktop` 都刪掉再重啟。以前裝的中台不會自動加上它。

#### 飛書（`feishu`）

用官方的 `lark-cli`：

```bash
npm i -g @larksuite/cli
lark-cli config init --new     # 建一個應用（你掃碼）
```

在開發者後台給應用開**機器人能力**，並訂閱**卡片回傳互動（長連接）**。然後：

```json
// rules.json
"channels": { "feishu": { "name": "飞书", "answerers": ["ou_用户的 open_id"] } }
```

```json
// config.json
"channels": { "feishu": { "key": "…", "user": "ou_用户的 open_id" } }
```

> **同一個飛書應用的卡片點擊只能有一個監聽，只在一台電腦上跑。**

實測狀況：飛書跑通了發送、按鈕回調和卡片更新。

#### 只會發文字的 Webhook（鉤釘 / 企微群機器人、Slack / Discord Webhook）

用 `plugins/webhook/channel.ts`。`config.json` 的通道項：

```json
"channels": {
  "dd": { "use": "webhook", "platform": "dingtalk", "url": "已有的 Webhook 地址", "key": "通道密钥" }
}
```

`platform` 四選一：`dingtalk`、`wecom`、`slack`、`discord`。

`rules.json` 裡要寫 `"links": true` — 這種通道靠**卡片連結本身**來回答，所以 `config.json` 的 `hub.publicUrl` **要配成你手機或電腦打得開的地址**。

訊息長度限制（`plugins/webhook/templates.ts` 會直接擋）：
- Discord 超過 2000 個字 → `Discord 消息超过 2000 个字，请缩短卡片`
- 企微超過 2048 bytes → `企微消息超过 2048 字节，请缩短卡片`
- 不認識的 platform → `没有这个 Webhook 模板：<名字>`

> **實測狀況：四種 Webhook 模板只在本地模擬服務上驗證過。**

#### 自己寫一個有按鈕的通道

在 `~/.agent-autoloop/plugins/<名字>/channel.ts` 寫一個，照 `plugins/feishu/channel.ts`：循環領卡片、發或改、報告；收到點擊轉給 `hub.answer`。用別的語言寫也行，只要會發 HTTP（直接當獨立程式連中台的 HTTP 協議，不必經過插件機制 — **通道不支援 `runtime: "process"`**）。

通道插件的四個呼叫：

| 呼叫 | 作用 |
|---|---|
| `hub.nextCard(50)` | 長輪詢領卡片，沒卡片回 `{ card: null }` |
| `hub.delivered(id, version, ref)` | 報告送達，保存外部訊息編號 |
| `hub.failed(id, version, error)` | 報告發送失敗 |
| `hub.answer(id, { choice, by, ref })` | 轉交回答；要核對回答人和原訊息 |

`ref` 為空就發新訊息，有值就更新原訊息。**沒報告的卡片一分鐘後重派。**

#### `answerers` 的安全提醒

`doctor` 會對沒寫 `answerers` 又不是 `links` 的通道給一條 `◐`：

```text
◐ 飞书没写 answerers：这个通道里谁都能回答卡片。
```

### 6.2 事件來源（活從哪來）

三種進法：

**1. 對方能發標準 HTTP JSON** — 不用寫插件

```bash
agent-autoloop key new source <名字>    # 先問使用者，這是新建密鑰
```

`rules.json` 的 `sources` 登記，對方 `POST /v1/events`：

```
POST /v1/events                    Authorization: Bearer <來源的密鑰>
{ "id": "12:new", "type": "feedback.new", "subject": "#12", "summary": "…", "detail": "…", "link": "https://…" }
→ 200 { "event": 34, "duplicate": false, "routed": ["处理意见"] }
```

規則：
- `id` 和 `type` 必填。**同一來源同一 `id` 只記一次**，所以來源儘管重發。
- `subject` 只能是識別字（字母、數字和 `# . _ : / @ -`），`link` 只能是純 ASCII 網址 — 因為它們**會進提示詞**。`summary`、`detail` **不進提示詞**。
- 沒有規則匹配的事件也留著，`status` 看得到。
- 欄位上限：`id` 200 字、`subject` 100、`summary` 200、`detail` 4000、`link` 500、`type` 64 個字元。

**2. 對方有自己的 Webhook 格式** — 寫一個事件插件

在 `~/.agent-autoloop/plugins/<名字>/source.ts` 寫一個函數，驗簽並翻譯成事件（照 `plugins/github/source.ts`）。來源寫 `"adapter": "<名字>"`，地址是 `/v1/in/<來源>`。

**驗簽用的秘密放 `~/.agent-autoloop/secrets.env`**，變數名是 `AGENT_AUTOLOOP_SECRET_<來源>`（來源名轉大寫，`-` 換成 `_`）。例如來源叫 `shop` → `AGENT_AUTOLOOP_SECRET_SHOP`。**改完要重啟中台**（`agent-autoloop service install`）。秘密**不進 `rules.json`**。

內建兩個：

| 來源 | 檔案 | 實測狀況 |
|---|---|---|
| `github` | `plugins/github/source.ts` | — |
| `gitlab` | `plugins/gitlab/source.ts` | 按官方文件的格式測試，**沒連過真實 GitLab** |

對方要能連到中台，所以中台要在伺服器上，或者用隧道。

**3. 對方推不過來，或中台在家裡** — 輪詢

定時跑一段腳本輪詢（見 `examples/watch-github-issues.sh`）。規則用 `use: "command"` 的 Agent，寫上 `emits`。**沒新東西不花 Token。** 事件的 `id` 要穩定，讀的範圍可以重疊，中台會去重；腳本要在回執交出去之後才推進自己的游標，或者乾脆不留游標。

**4. 定時（cron）** — 規則寫 `cron`

錯過的（例如電腦合蓋了）醒來只補最近的一次。重複的時刻（夏令時）只跑第一次，不存在的時刻跳過。

### 6.3 `tell` / `ask`：不經 Agent 直接找你

來源或 `elsewhere` 任務有話要直接告訴你：

```bash
echo "本周清理完成，删了 32 个分支" | agent-autoloop tell weekly-44
```

```text
说了。
```

同一個 `key` 只發一次，重複時：

```text
这件事已经说过了，这次没再发。
```

定時任務要你拍板：

```bash
echo '{"title":"要删这 5 个分支吗？","text":"都已合并超过 90 天。","options":["删","留着"],"recommend":0,"key":"sweep-44"}' | agent-autoloop ask --task 每周清理
```

```text
问了。
```

`rules.json` 裡這個定時任務**要寫 `cwd`**（還要 `skill` 或 `prompt`）。你答了，中台會叫醒它的 Agent 在 `cwd` 照 `skill`/`prompt` 接著做，回答在這一輪資料檔的 `answers` 裡。沒寫 `cwd` 的任務問你會回 400。

四個方向都能自由替換。**內建插件隨程式安裝，填好配置就啟用；第三方插件用 `agent-autoloop add <git 地址>` 安裝。**

### 7.1 內建 11 個一覽

| `desktop` | channel | 桌面通知（macOS `osascript` / Linux `notify-send`） | 兩處各寫一個 `desktop`（新裝預設有） |

共 11 個插件、22 個檔案（含 `plugins/delivery/action.yml`）。

### 7.2 交付流水線（`delivery`）

給 GitHub PR 打上 `deliver` 標籤後，它會自己跟進到上線：**審程式碼 → 等 CI → 合併 PR → 等部署 → 核對線上版本**。

前置：這台接單電腦要有 **`gh` 已登入**和審查程式。

安全邊界（重要）：**審查和交付配置只從 `main` 讀取，絕不在接單電腦上檢出或執行 PR 裡的程式碼。** 排隊、並發和重試直接複用核心。

專案的 `ops/delivery.json` 要放到 main：

```json
{
  "repo": "owner/app",
  "internal": ["docs/**/*.md"],
  "check": { "workflow": "check.yml", "job": "check" },
  "ship": { "workflow": "ship.yml" },
  "review": { "points": "AGENTS.md", "status": "agent-review", "xhigh": ["src/auth/*"] },
  "health": {
    "url": "https://app.example/health",
    "field": "commit",
    "pattern": "(?P<sha>[0-9a-f]{40})",
    "require": { "ok": true }
  }
}
```

標籤語意：

| 標籤 | 意思 |
|---|---|
| `deliver` | 進入完整流程 |
| `deliver-review` | 只審查；在等待檢查期間加上也會阻止合併 |
| `deliver-attended` | 有人盯著，發現問題只寫回執、不另發通知 |
| `ask-owner`（普通 issue） | 變成一張問題卡片，回答後去掉標籤；**不替你在 GitHub 發評論** |

幾個細節：
- `AGENTS.md` 要有 `## 审查要点`。
- `check.job` 寫 job 的名字；矩陣 job（名字像 `check (ubuntu-latest)`）算同一個 job，每一項都要成功。
- 檢查工作流的觸發類型要帶 `ready_for_review`，否則草稿轉 ready 後 `pull_request` 預設不觸發。
- `admin_merge` 預設為空；只有 main 明確列出的 PR 作者才能用管理員合併。
- 沒有線上服務的專案可以省略 `health`，回執會明確寫只完成合併。
- 健康接口普通運行**只允許 HTTPS**；`--test-local-health` 僅用於明確的本機測試（額外允許 `http://127.0.0.1`）。
- 審查發現問題後，同一個提交不再審第二次；修復後推新提交才重新審查。

完整的規則範例見 `skills/agent-autoloop/SKILL.md` 的「交付流水線」一節。

### 7.3 第三方插件：`agent-autoloop add`

```bash
agent-autoloop add https://github.com/someone/my-plugin.git
agent-autoloop add D:/dev/my-plugin          # 也接受本機 Git repo
```

**它會改什麼：** `git clone -- <url> ~/.agent-autoloop/plugins/<名字>`。**只 clone，不裝依賴、不跑安裝腳本、不自動更新。**

插件名字 = 來源末段轉小寫，只能用**小寫字母、數字和 `-`**。規則的 `use` 和來源的 `adapter` 都寫這個名字。

```text
已安装 my-plugin。
它没有声明 runtime，按源码插件用（runtime: "source"）：中台加载它的时候会执行它。
```

或者：

```text
已安装 my-plugin。
它声明自己是一个外部程序（runtime: "process"），跑的是 bin/my-plugin.exe
```

拒絕的情況：

```text
插件名字「My_Plugin」不能用：只能用小写字母、数字和 -，规则里的 use 也写这个名字
```

```text
「C:」只是一个盘符，不是一个地址：写全要装的那个仓库的路径或 URL（比如 C:/path/to/plugin）。
```

```text
安装失败。
```
（git clone 沒成功）

```text
但它的 plugin.json 写错了：<原因>
```

> **⚠️ 插件是可信程式碼，先讀再裝。** 源碼插件被中台 `import` 就等於**以中台的身分執行**。`host/plugins.ts` 的載入就是執行。
>
> **同名的本機插件優先於內建插件。**

一個插件就是一個目錄，入口為 `agent.ts`、`channel.ts` 或 `source.ts`。只用 `node:` 模組和自己目錄裡的檔案，類型在插件裡宣告；**不要相對引用引擎原始碼** — 裝在 `~/.agent-autoloop/plugins/` 的插件，相對路徑到不了引擎。

### 7.4 `plugin.json` 與 process 模式

插件目錄裡可以有一個 `plugin.json`（可選），`runtime` 只有兩個值：

| `runtime` | 意思 |
|---|---|
| `source`（預設） | 入口是 `agent.ts` / `channel.ts` / `source.ts`，中台把它 `import` 進自己這個進程。**載入就是執行** |
| `process` | 入口是 `entry` 指的一個可執行檔，中台每次呼叫起它一次，走標準輸入輸出的逐行 JSON |

沒有這個檔案、讀不出來、不是物件、或沒寫 `runtime`，一律當 `source`（第三方 repo 本來就可能有一個講它自己事情的 `plugin.json`）。寫明了 `runtime` 又寫錯（不是這兩個值、`process` 沒有 `entry`、`entry` 是絕對路徑或走出插件目錄）**則直接報錯**。

```json
{ "runtime": "process", "entry": "bin/my-plugin", "args": ["--quiet"] }
```

- `entry` 是**插件目錄內的相對路徑，走不出去**。
- `args` 可選，每次呼叫都在最前面，是參數而不是 shell 詞（不經 shell、不做字串拼接）。
- 程式跑起來時的當前目錄就是插件自己的目錄，所以 `args` 裡寫相對路徑就能指到自己的檔案。
- **`entry` 也不能借 symlink / junction 出界** — 比的是**真實路徑**（`realpathSync`），不是寫法。連接盡頭什麼都沒有的也當出界處理。

呼叫方式：每次起一個進程，stdin 給一行 JSON 請求，stdout 的**最後一行**是 JSON 答覆，然後退出。答覆是 `{"ok":true,"value":…}` 或 `{"ok":false,"error":"一句人能照着做的话"}`；中間想印別的東西可以，只要答覆在最後一行。

| 請求 | 對應的函數 | `value` |
|---|---|---|
| `{"call":"describe"}` | — | `{"calls":["command","read","link","check"]}`，只用來問它有哪幾個 |
| `{"call":"command","turn":{…}}` | `command(turn)` | 命令參數陣列 |
| `{"call":"read","stdout":"…","code":0,"stderr":"…"}` | `read(stdout, code, stderr)` | `Reading` 物件，執行中 `code` 是 `null` |
| `{"call":"link","session":"…"}` | `link(session)` | 連結字串 |
| `{"call":"check"}` | `check()` | `null` 或一句話 |
| `{"call":"translate","headers":{},"body":"","secret":""}` | 事件插件的那個函數 | 事件陣列 |

**`describe` 每個進程只問一次。** 中台第一次取這個插件時問它有哪幾個 call，往後就記著了。代價是：**插件改了要重啟中台才算數**（`agent-autoloop up` 重起一次）。改了 `plugin.json`、換了 `entry` 指的程式、給插件加了一個 `link` 或 `check`，在跑著的那個中台裡都還是舊的。沒做成的插件不進這個記憶 — 報了錯的下一次會再問一遍，所以修好一個起不來的插件不必重啟。

**通道不支援 `process`。** 通道是和中台一樣長命的迴圈，不是一次一答的翻譯。用別的語言寫通道，直接當獨立程式連中台的 HTTP 協議。

#### Windows 上 process 模式的限制

**`entry` 必須是插件目錄裡一個真正的可執行檔（`.exe`）**，和 Agent 程式一樣。這裡不經過 shell，CreateProcess 認什麼就是什麼：

- `.cmd` / `.bat` 包裝起不了（`EINVAL`）
- `#!/bin/sh` 腳本也起不了（`EFTYPE`，Windows 不看 shebang）
- `entry` 走不出插件目錄，所以也不能指向目錄外的 `node.exe` 或別的解譯器

要在 Windows 上發一個用解譯器跑的插件，就把那個解譯器放進插件目錄裡，腳本寫在 `args` 裡：

```json
{ "runtime": "process", "entry": "runtime.exe", "args": ["handler.mjs"] }
```

跨平台的插件按平台寫兩份 `plugin.json`，或者乾脆帶一個各平台的原生可執行檔。

### 7.5 二進位模式的限制

以單一二進位分發的版本裡，內建插件是編進去的（建置期產生一張靜態清單，不進版本庫），但**它沒有辦法跑外部的 `.ts` 檔案**。所以裝在 `~/.agent-autoloop/plugins/` 的第三方插件：

| | 原始碼模式 | 打包版（二進位） |
|---|---|---|
| `runtime: "source"` | 照舊能用 | **報一句話，叫你改成 `runtime: "process"`** |
| `runtime: "process"` | 能用 | 能用 |

開發插件時用原始碼模式最方便；要分發給用打包版的人，就帶一份 `process` 入口。

### 7.6 寫自己的插件

從三個**可執行的最小模板**開始：

| 模板 | 已經示範了什麼 | 你要替換什麼 |
|---|---|---|
| `examples/plugins/hello-agent/agent.ts` | 用 `printf` 模擬執行，讀取輸出、會話編號和「收下了提示詞」 | 新 Agent 的啟動命令和輸出解析 |
| `examples/plugins/hello-channel/channel.ts` | 領卡片、寫到檔案、報告送達；透過命令列回答 | 目標平台的發送、更新和回答回調 |
| `examples/plugins/hello-source/source.ts` | 驗證 HMAC-SHA256 簽名，把模擬訂單轉換成事件 | 業務系統的驗簽方式和欄位映射 |

先在引擎目錄跑一遍（把三個例子分別裝進臨時中台，實際走完驗簽、派活、執行、通知和報告，退出後清理）：

```bash
node --disable-warning=ExperimentalWarning --test --test-name-pattern='agent-autoloop add' tests/example-plugins.test.ts
```

Agent 插件要匯出的四個方法：

| 方法 | 作用 |
|---|---|
| `command(turn)` | 回傳命令參數陣列；參數不作為 shell 程式碼執行 |
| `read(stdout, code, stderr)` | 回傳 `text`、`session`、`usage`、`sessionUsage`、`error`、`finished`、`started`；執行中 `code` 為 `null` |
| `link(session)` | 可選，打開這個會話的連結 |
| `check()` | 可選，能用回傳 `null`，否則回傳下一步怎麼做 |

兩個最容易踩的坑：

1. **支援 `resume` 的插件，從 Agent 收下提示詞起都要回傳 `started: true`**（包括執行中和出錯之後）。否則幹到一半斷了，會被當成會話接不上，開新會話把業務重做一遍。
2. **回傳了 `session` 就要按 `turn.resume` 接回原會話**；接不回去的 CLI 不要回傳 `session`。

接插件前先在**專用測試中台**驗證：

```bash
agent-autoloop conformance <測試中台地址> --config <測試憑據檔>
```

**它會寫事件和卡片，只對專用測試中台執行。** 協議類型在 `protocol/schema.json`。

### 7.7 MCP

MCP 客戶端的啟動程式填 `node`，參數為本機引擎絕對路徑 `bin/agent-autoloop.ts`、`mcp`，環境裡傳 `AGENT_AUTOLOOP_HOME`。支援 stdio 2025-11-25 版，使用本機 `config.json` 已有密鑰，**不把密鑰寫進客戶端參數**。

> ⚠️ **MCP 服務不區分呼叫方，都按本人記錄**（`answer` 記成本人，`emit` 不帶層數）。**不要把它配進接單程式啟動的 CLI 的使用者級配置**，否則一輪能自己回答自己的卡片。

## 8. Windows 專章

**原生支援，不需要 WSL2。** 但有四處降級，和一處看得見的開銷。

### 8.1 四處降級

#### 降級 1：桌面通知一律跳過

Windows 上沒有這個專案可用的通知程式（WinRT toast 是後續的工作），所以卡片走「skipped」路徑 — **行為是正確的，只是沒有通知**。

卡片仍然進 `agent-autoloop status` 和別的通道。`doctor` 會給一條 `◐`：

```text
◐ 桌面通知不可用：Windows 上没有可用的通知程序，卡片会跳过通知
```

對策：接一個真的通道（飛書、鉤釘、企微、Slack、Discord），或者習慣自己敲 `status`。

#### 降級 2：常駐靠排程任務，停了最多等 5 分鐘

沒有「不需要管理員的使用者級服務管理器」，所以常駐用的是**你自己的排程任務**（`schtasks`，由 XML 註冊）：

- **登入時啟動**（`LogonTrigger`）
- **每 5 分鐘重複觸發**（`PT5M` 的 `TimeTrigger` + `Repetition`）
- `MultipleInstancesPolicy` 是 `IgnoreNew`：一個在跑時下一個直接丟掉（和 `up.pid` 給的答案一樣，只是早一步）
- `ExecutionTimeLimit` 是 `PT0S` = 沒有上限（它本來就要一直在）
- `RestartOnFailure`：間隔 1 分鐘、最多 3 次
- `LogonType` 是 `InteractiveToken`、`RunLevel` 是 `LeastPrivilege` — **不需要管理員**
- 任務不帶環境變數，所以這個安裝用的 HOME 是透過 `node --env-file=<HOME>\service.env` 傳進去的

和 launchd / systemd 的語意差別就在這裡：**它崩了不是立刻回來，是最多等 5 分鐘。**

**加了網域的電腦還不讓「登入時啟動」**，這時登入後也要等最多 5 分鐘。`doctor` 會把這兩種情況分開講（見 3.6）。

這套常駐的檔案：`%USERPROFILE%\.agent-autoloop\service.xml`（註冊用的 XML）、`service.env`（HOME）。中台自己認得哪個排程任務是它的 — 靠寫在任務描述裡的一段 ASCII 指紋（`install:<sha256 前 16 字>`，由 HOME + 程式路徑算出來），因為已註冊的任務讀回來會帶上 console 的編碼頁，路徑裡有中文就對不上了。

#### 降級 3：檔案權限用 `icacls`，鎖不上不攔著啟動

Windows 沒有 `0700` / `0600`（`chmod` 只動一個唯讀位元）。改用 `icacls` 把資料目錄的權限鎖到當前使用者：

```
icacls <目錄> /inheritance:r /grant:r "<USERNAME>:(OI)(CI)F"
```

- `/inheritance:r` 拿掉上層授予的
- `/grant:r` 取代這個使用者自己的條目而不是疊加
- `(OI)(CI)` 讓裡面寫進去的檔案和目錄繼承同一套
- `master.key` 另外單獨鎖一次

**鎖不上（網路磁碟、FAT32、網域策略）不會攔著啟動**，而是把結果寫在 `~/.agent-autoloop/permissions.json` 旁邊，`doctor` 讀回來報一條：

```text
◐ 文件权限降级：icacls 没能锁定 C:\Users\你\.agent-autoloop
```

或者：

```text
◐ 文件权限降级：不知道当前用户是谁（USERNAME 没有设）
```

**這時同機的其他使用者可能讀得到你的資料庫、事件和執行輸出。**

注意這條紀錄只記**這一次**的結果，不是歷史上每一次 — 否則一台電腦的 home 從網路磁碟搬到本機磁碟之後，還會一直說它做不到某件事，而你什麼也不能做。

#### 降級 4：Agent 必須是真的執行檔

見 [5.2](#windows-上的安裝位置注意重要)。npm 裝出來的 `.cmd` 包裝腳本起不了，`init` 會說找不到。同樣的規則也套用在 `plugin.json` 的 `entry`（見 7.4）。

### 8.2 進程樹取樣開銷（不是降級，但你會看到）

POSIX 上一輪的子孫進程靠 **process group** 管，殺一次就全乾淨。**Windows 沒有 process group**，所以要在這一輪停下來的時候找得著孫子進程，worker 得定期走一遍**整張進程表**。

實測（Windows 11，`phase3-verification-round2.md`）：

| 量 | 實測 |
|---|---|
| 走整張進程表 | 1.3–1.6 秒 |
| `sampleTree` | 1.8–1.9 秒 |
| `/healthz` p50 | 1 ms |
| `/healthz` p95 | 1.55 秒 |
| `/healthz` max | 1.86 秒 |
| 取樣週期 | 預設 30 秒一次（`SAMPLE_EVERY = 30_000`） |
| 結果 | **單一個 run 在跑時，中台約 6% 的時間會慢** |

人話：**有一輪在跑的時候，中台每 30 秒會有一次大約 2 秒不應答。** 所以這時候 `status` 一類的命令偶爾會慢這麼一下。沒有 run 在跑時不取樣，不會有這個開銷。

要調（主要給測試用）：環境變數 `AGENT_AUTOLOOP_TREE_SAMPLE`（毫秒，整數且 ≥ 0；`0` 等於每次都走）。

> 多個 run 同時取樣的延遲疊加 **【待確認】** — `phase3-verification-round2.md` 明確把它列在「未驗證」。

### 8.3 PowerShell 5.1 vs 7

`install.ps1` 的註解明寫：**寫給 Windows PowerShell 5.1 也寫給 PowerShell 7** — 5.1 是新機器本來就有的，而這是任何人在新機器上跑的第一件事。驗證報告也確認了 `install-smoke.ps1` 在 **pwsh 7 與 PS 5.1 都 exit 0**。

兩邊有幾個差別，自己寫腳本呼叫 `agent-autoloop` 時要知道：

| 項目 | Windows PowerShell 5.1 | PowerShell 7 |
|---|---|---|
| 原生命令寫到 stderr 的每一行 | **都算一個 error**（`$ErrorActionPreference = "Stop"` 下會中斷你的腳本） | 不會 |
| `$PSNativeCommandUseErrorActionPreference` | 沒這個變數（賦值無害） | 有；設 `$false` 才能讓 `doctor` 自己的 exit code 當報告讀而不是當錯誤拋 |
| UTF-8 | 要自己設 `[Console]::OutputEncoding` 和 `$OutputEncoding`，否則 node 寫出來的 UTF-8 會被 console 編碼頁解錯 | 同樣建議設 |

`install-smoke.ps1` 開頭就是這三行，照抄即可：

```powershell
$PSNativeCommandUseErrorActionPreference = $false
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
```

另外：`.cmd` 的 shim 是**刻意寫成 ASCII** 的 — `.cmd` 會用 console 當時的編碼頁讀，所以這個檔案必須在所有編碼頁下都長一樣。

### 8.4 還是想用 WSL2

按 Linux 裝，但要注意：

- 系統服務要發行版開著 systemd（`/etc/wsl.conf` 裡 `systemd=true`）。沒開就加 `--no-service`，自己跑 `agent-autoloop up`。
- 沒人登入時要啟動，要 `loginctl enable-linger`。
- 桌面通知也到不了 Windows 桌面。
- WSL2 本身還要佔 1 GB 左右記憶體。

### 8.5 Windows 上的停止與單例鎖

- **別直接殺 `up` 的進程。** 往 `AGENT_AUTOLOOP_HOME` 下寫一個空的 `stop` 檔案，中台看到就自己收尾（`fs.watch`）。`uninstall` 也是這麼停的。
- Windows 沒有 SIGTERM 可送，`process.kill(pid, "SIGTERM")` 在那裡就是硬殺，目標收不到事件，`finish()` 永遠不執行。硬殺會留下 `up.pid` 和沒關的連線。
- **留下的 `up.pid` 擋不住下一次 `up`**：裡面記著那個進程的創建時刻，認得出是遺留的。
- 列不到進程時 `up` 會說：
  ```text
  看不清 C:\Users\你\.agent-autoloop\up.pid 里的号还在不在（列进程没成功）：确认没有别的 up 在跑之后，把它删掉再来
  ```

## 9. 疑難排解

### 9.1 `doctor` 的三種符號

| 符號 | 意思 | exit code |
|---|---|---|
| `●` | 好了 | 不影響 |
| `○` | **紅項** — 真的壞了，照後面那句話做 | 有任何一條就 **exit 1** |
| `◐` | **降級說明** — 能用，只是不如字面承諾的那麼多 | 不計入 |

### 9.3 幾個特定情境

#### 殘留 `up.pid`

Windows 上硬殺 `up` 會留下 `up.pid`。設計上它**擋不住下一次 `up`** — 檔案裡記著那個進程的創建時刻，認得出是遺留的。真正會卡住的只有「列進程失敗」那一種，這時 `up` 會印出上面那句話，你確認沒有別的 `up` 在跑之後手動刪掉它。

正確的停法：往 `~/.agent-autoloop/stop` 寫一個空檔案。

#### 找不到 `claude` / `codex`

檢查順序：

1. `where.exe claude`（Windows）/ `command -v claude`（POSIX）有沒有輸出。
2. **輸出的是不是 `.exe`？** Windows 上 `.cmd` / `.bat` 一律不算。
3. 不在 PATH 上時，看 5.2 列的那些 fallback 路徑有沒有東西。
4. `agent-autoloop doctor` 會對本機 worker 的 Agent 跑一次 `check()`，把具體原因印出來。

#### 中台間歇性慢 / `fetch failed` 一次

Windows 上有 run 在跑時，每 30 秒會有一次約 2 秒不應答（見 8.2）。驗證報告另外記了一件事：取樣期間出現過 **1 次** `couldn't reach the hub`（對照組 0 次），**因果未定**，`watchHub` 容忍單次閃斷。

#### 規則改了沒生效

- 先 `agent-autoloop check`：寫錯了舊規則會繼續跑。
- 再 `agent-autoloop rules explain` 看中台認到的樣子。
- 排隊中與等待重試的任務會在**領取時**才採用最新的 Agent、目錄、提示詞和權限；**已經領取的任務保留領取時的配置到這次執行結束**。
- 改的是 `config.json`（不是 `rules.json`）→ **要 `agent-autoloop service install` 重啟。**
- 改的是插件 → **要重啟中台**（`describe` 每個進程只問一次）。
- 改的是 `secrets.env` → **要重啟中台。**

## 11. 解除安裝

```bash
agent-autoloop uninstall          # 終端機裡確認後才執行
agent-autoloop uninstall --yes    # 非互動時跳過確認
```

**預設保留規則、密鑰和紀錄。**

它只做這些事：

- 停自己的服務和進程（Windows 上是寫 `stop` 檔讓中台自己收尾）
- 刪掉指向自身的命令（Windows：`agent-autoloop.cmd`，會先讀裡面寫的程式路徑確認是自己的才刪）
- 刪掉 Skill 連結（Windows 用 junction；junction 也建不了時安裝器會改成複製，並在 `<HOME>/skill-link.json` 記下來 — 卸載按這條紀錄刪掉那份複製，**SKILL.md 內容不一致就不動**）
- 刪掉安裝目錄裡的 `app`

輸出：

```text
删掉了 C:\Users\你\.local\bin\agent-autoloop.cmd
删掉了 C:\Users\你\.claude\skills\agent-autoloop
删掉了 C:\Users\你\.agent-autoloop\app
卸载好了。规则、密钥和记录还留在 C:\Users\你\.agent-autoloop。
```

**其他同名檔案不動；資料目錄不刪除。**

要收尾乾淨的話：

- **PATH 裡那一行要自己去「編輯帳戶的環境變數」刪。**（Windows）
- 真的不要資料了，自己刪 `~/.agent-autoloop`（**裡面有 `master.key` 和你的密鑰**）。
- 二進位模式：`uninstall` **不刪你下載的那個 exe** — 那是你放的。

`install-smoke.ps1` 對 `uninstall` 的斷言（也就是它承諾的行為）：
- `hub\config.json` 還在（沒刪資料）
- `hub\app` 不在（源碼模式）
- shim 不在
- `/healthz` 連不上（中台真的停了）
- 整個假的 `USERPROFILE` 底下一個檔案都不剩

- `access` 不是中台提供的系統沙箱，是插件翻譯給各家 CLI 的權限模式。
- 二進位不是可重現建置（blob 裡帶 V8 code cache）。
- **內核與協定那一層的字串還是簡體，會和正體的介面夾在一起。** 具體是：卡片網頁上的按鈕、`cron` 的說法（例如「每周一」）、規則檢查的訊息、內建來源名「定时」。原因是 purity 約束不准內核讀環境，它拿不到語言；要修就得把語言當資料一路傳進去，留待後續。

### 12.4 標了「待確認」的清單

1. **多個 run 同時取樣的延遲疊加** — `phase3-verification-round2.md` 明確列為未驗證。
